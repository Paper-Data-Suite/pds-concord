# v0.3.1 Routine Artifact Scoring

**Status:** Issue #108 implementation contract and teacher workflow

Issue #108 streamlines explicit teacher scoring from one exact current reviewed
Artifact without changing Concord's canonical `ScoreRecord`,
`ScoreEvidenceLink`, Review, Moderation, attribution, or correction models.

## Teacher workflow

For ordinary reviewed returned work:

```text
reviewed Artifact
    ->
Score this work
    ->
Open returned work if needed
    ->
choose explicit Target
    ->
choose explicit Criterion
    ->
use or choose a valid current Scale
    ->
choose exact native Scale value
    ->
review Subject / Session / evidence context
    ->
preview complete Score
    ->
SCORE
```

For several Criteria on the same work:

```text
SCORE
    ->
Score another Criterion
    ->
reload current canonical Activity state
    ->
choose a fresh Criterion
    ->
choose a fresh exact Scale value
    ->
SCORE
```

For another piece of score-ready work:

```text
SCORE
    ->
Next score-ready work
    ->
reload current canonical Activity state
    ->
deterministically select another current score-ready Artifact
```

Advanced Score recording remains available for external evidence, multiple
Evidence Links, professional judgment, mixed basis, unusual Session or Subject
context, non-routine dispositions, and Score revision/correction.

## Exact projection

`ArtifactRoutineScoringContext` is an ephemeral read-only projection over one
exact `ActivityReadContext` loaded by `load_activity_read_context(...)`.

It includes the exact selected Artifact, current Review, current Authors,
current Subjects, typed Subject-context candidates, selected current Criterion
Sets and Criteria, current Scales, current Sessions, current Groups and
Memberships, current Score heads, and the exact snapshot revision/SHA-256.

Routine scoring eligibility != automatic Score.

A Review that permits scoring only makes the Artifact eligible for teacher
consideration. It does not mean that a Score is required, missing, or already
selected.

## Native Artifact evidence

`native_artifact_evidence_reference(...)` constructs the existing Concord native
Artifact `EvidenceReference` for the selected Artifact. The teacher does not
re-enter Artifact machine identity.

Routine Artifact scoring uses the existing linked-evidence semantics:

```text
ROUTINE_SCORE_BASIS = linked_evidence
ROUTINE_SCORE_DISPOSITION = scored
```

The visible deterministic relevance default is:

```text
Returned Artifact evidence for this Score.
```

`OPEN != SCORE`: opening the exact selected returned work through the #105
boundary is read-only and creates no Score, Review, Moderation, attribution, or
Artifact mutation.

## Explicit target and Criterion

No Score target is inferred from `ArtifactAuthor` or `ArtifactSubject`.

Current Author and Subject relationships may produce teacher-visible candidate
context, but the teacher must explicitly choose the Score target.

`routine_target_options(...)` exposes current legal candidates without selecting
one. `routine_criteria_for_target(...)` then limits the teacher's Criterion
choices to current selected Criteria compatible with that explicit target.

Existing Scores do not create an assessment completion matrix.

Concord does not infer:

```text
missing Score
required Score
student x Artifact x Criterion completion
group x Artifact x Criterion completion
Artifact x Criterion completion
```

from the presence or absence of current Score records.

## Scale and value

`routine_scale_options(...)` preserves exact current native Scale authority.

A valid current Criterion default Scale is a convenience only. It does not
select a Score value, and Concord does not substitute another Scale silently
when the configured default is missing, historical, or inactive.

The Score value remains an explicit teacher judgment and must match one exact
native Scale level. Native values remain type-exact; for example, `1`, `1.0`,
`"1"`, and `true` are not normalized into one value.

## Subject and Session context

`routine_subject_context_options(...)` exposes current confirmed Artifact
Subjects as typed identities when they are legal for the selected Criterion.

No Subject context is inferred from Author.

Session context remains explicit and canonical. An Artifact Session may be shown
as an operation-local convenience, but no Session is guessed from chronology,
Group membership, or proximity.

## Preview and confirmation

`prepare_routine_score_preview(...)` produces an idless, read-only
`RoutineScorePreview`.

The preview contains the teacher-significant decision:

```text
Artifact
Target
Criterion
Scale
Value
Session
Disposition
Basis
Evidence
Subject context
Moderation
Relevance
```

No Score or Evidence Link ID is generated during projection or preview.

Only explicit final `SCORE` confirmation may call
`record_prepared_routine_score(...)`.

## Canonical write boundary

`record_prepared_routine_score(...)` generates opaque Score and Evidence Link
IDs internally and constructs one canonical `AddScoreRequest`.

`add_score(...) remains the mutation authority`.

The final write carries the exact previewed snapshot revision. A relevant stale
change fails closed; Concord does not silently retry or rebase the teacher's
decision.

Routine scoring creates only the canonical Score and required native Artifact
Evidence Link. It does not implicitly create or mutate:

```text
ArtifactReview
ModerationRecord
Grade
ArtifactAuthor
ArtifactSubject
Artifact assembly
Publication
Group Membership
Criterion
Criterion Set
Scoring Scale
Session
```

A current Score for the same explicit target + Criterion routes away from
parallel first-entry creation. Score revision continues to use the existing
successor Score + `CorrectionRecord` audit model.

## Score another Criterion

`reload_routine_scoring_after_score(...)` reloads current canonical state after
every successful routine Score.

Only still-valid operation-local values may survive:

```text
selected Artifact evidence
selected explicit Score target
valid Session context
```

The next Score requires a fresh explicit Criterion and exact Score value. It
does not automatically reuse the previous Criterion, Scale when incompatible,
value, Subject-context selection, rationale, or Moderation decision.

`prepare_next_routine_score_preview(...)` therefore starts from a fresh
post-commit projection rather than a stale pre-commit Activity graph.

No persistent Score queue, score cursor, last-scored Artifact, or scoring-session
record exists.

## Next score-ready Artifact

`inspect_next_score_ready_artifact(...)` is read-only and derives readiness from
the same canonical semantics behind `concord_score_ready`.

Score-ready Artifact != missing Score.

A score-ready Artifact with an existing Score may still be valid evidence for
another teacher-selected Score because readiness describes current reviewed
evidence, not assessment completion.

The selector reloads current Activity state, orders current Artifacts
deterministically, selects another ready Artifact relative to the current
operation-local Artifact, wraps once when necessary, and never returns the
current Artifact as its own next item.

When no other current score-ready Artifact exists, navigation terminates
truthfully without claiming that all scoring is complete.

## Moderation

Routine scoring creates no Moderation decision.

Existing Review/evidence Moderation requirements remain authoritative.
Preparation fails closed when routine evidence use requires unresolved
Moderation, and canonical `add_score(...)` remains the final Moderation
enforcement boundary.

## Import boundary

Issue #107 exposed an Activity-attention / Share-attention / manifest-generation
import cycle. Issue #108 preserves the #107 lazy-delegate pattern.

Score-next reuses the canonical Activity-attention
`_score_state_from_context(...)` semantics through lazy runtime delegation
rather than defining score-ready twice.

The isolated import-boundary regressions preserve manifest-generation imports
and the new score-next dependency edge.

## Qualification

Installed-wheel qualification is provided by:

```text
scripts/smoke_test_routine_artifact_scoring_wheel.py
```

The installed acceptance authenticates released Core 0.6.3, runs `pip check`,
executes under `python -I`, verifies `site-packages` provenance, creates two
synthetic reviewed Artifacts, records two sequential explicit routine Scores
with a canonical reload between them, and verifies deterministic navigation to
another score-ready Artifact.

It also proves that Review, Moderation, attribution, Artifact, and publication
state are not implicitly mutated and that Advanced Score recording remains
reachable.

The runtime dependency remains:

```text
pds-core>=0.6.3,<0.7
```

No existing v0.3.0/v0.3.1 workspace data migration is required solely for
Issue #108.

**Issue:** #123 — Descriptive Activity Score Analysis and Local Reports  
**Release target:** Concord v0.3.1  
**Generated-path authority:** [`v0.3.1-generated-path-safety.md`](v0.3.1-generated-path-safety.md)  
**Final qualification baseline:** released `pds-core 0.6.4`

## Purpose and semantic boundary

Issue #123 adds a teacher-facing descriptive analysis layer over existing
Concord Score records for one exact Activity state.

The governing boundary is:

```text
descriptive Concord Score analysis
!=
Grade calculation
!=
proficiency/mastery inference
!=
formal Meridian reporting
```

The human-readable report boundary is explicit:

> Concord Activity Score Analysis describes current Concord Score records. It
> does not calculate Grades, proficiency/mastery, required/missing Scores, or
> Academic Period results.

Existing Scores are observations. They are not evidence that every target was
required to receive every Criterion, and #123 does not create a completion
matrix, missing-Score count, implicit zero, or average.

## Exact Activity read boundary

Analysis starts from one exact verified `ActivityReadContext`.

The normal analysis population is:

```text
current Score lineage heads only
```

Superseded Scores are not additional current judgments. Explicit Score History
remains a separate teacher-local view that walks stored replacement lineages.
No persistent analytics database or cache is introduced.

## Target identity

These target kinds remain distinct:

```text
core_student
concord_group
concord_artifact_instance
concord_session
concord_activity
```

A Group Score is not expanded into student Scores. Artifact Author or Subject
identity is not substituted for the recorded Score target.

## Criterion, Scale, and disposition analysis

Criterion analysis preserves the exact represented Criterion, Scoring Scale,
Scoring Scale revision, and target kind. Multiple Scale revisions are never
silently combined. Native Scale values stay type-sensitive.

For a Scale-value distribution:

```text
denominator =
scored current judgments in the exact
Criterion / Scale revision / target-kind slice
```

For a disposition distribution:

```text
denominator =
all current Score heads in the exact
Criterion / Scale revision / target-kind slice
```

Terminal, CSV, JSON, and PDF surfaces consume the same derived numerator,
denominator, and deterministic percentage values.

These non-score dispositions never become zero, failure, or a Scale value:

```text
insufficient_evidence
absent
excused
not_observed
not_applicable
deferred
```

## Standards / Criterion view

Standard-backed Criteria may be grouped by durable Core Standard ID. Multiple
Criteria for one Standard remain distinct and local Criteria stay outside the
Standards grouping. Teacher-readable Standard labels fall back to the durable
`standard_id` when Core label resolution is unavailable.

Concord does not infer standards proficiency or mastery.

## Target Detail

Target Detail shows current Score observations for one exact selected target,
including the teacher-readable target label, target kind, Activity, Criterion,
exact Scale revision, exact value or non-score disposition, and timestamp.

The default scope is:

```text
teacher_local
```

It is not automatically student-facing, parent-facing, share-safe, or a Grade
report. Current Target Detail excludes superseded revisions; Score History is
the separate explicit historical view.

## Local report scopes and formats

The Activity Analysis Report is aggregate and privacy-minimized. It includes
Activity identity/title, generated timestamp, exact snapshot technical metadata,
current-Score-head basis, target-kind counts, Criterion analysis, Scale-value
and disposition distributions, Standards / Criterion grouping when applicable,
and semantic-boundary statements. It does not include every target row.

The Target Detail Report contains only the selected target's current Score
projection and the teacher-local boundary statement.

JSON uses the versioned local contract:

```text
concord_activity_score_analysis_v1
```

This is not an Academic Result Manifest, Core Publication Record, Meridian
cache, Grade export, or SIS contract.

CSV uses deterministic fixed leaves:

```text
activity_overview.csv
criterion_distributions.csv
score_dispositions.csv
standards_criteria.csv
target_scores.csv
```

PDF is a first-class local report using Concord's existing Pillow PDF stack.
Large analyses paginate instead of shrinking text to fit. Fixed PDF leaves are:

```text
activity_analysis.pdf
target_detail.pdf
```

## Privacy-minimized projection

Default report models do not project:

```text
retained-source paths
route IDs
raw PDS2 payloads
Score rationale
Evidence Link detail
Moderation rationale
restricted peer identity
```

Technical snapshot identity is kept separate from ordinary presentation.

## Deliberate export workflow

The teacher path is:

```text
Open Activity
    ->
Score
    ->
Review Score Analysis
    ->
Export Report
```

Export follows:

```text
prepare exact immutable report
    ->
preview exact scope and destination
    ->
type literal GENERATE
    ->
write bounded local output
```

Before `GENERATE`, preview creates no report files. `B` or an empty
confirmation cancels without output. The preview states the class, Activity,
scope, Score basis, represented Score count, target-row/history/Grade flags,
format, exact bounded destination, and output leaves.

Existing identical output may be verified and reused. Conflicting output is
never silently overwritten. The result remains local teacher-controlled output
and is not described as sent, shared, delivered, filed, approved, or received.

## #124 generated-path contract

Issue #123 does not define a second path policy. Canonical packages use:

```text
exports/
  score_analysis/
    cgo_<24 lowercase SHA-256 hex>/
      <fixed report leaves>
```

The package token comes from
`concord.generated_paths.build_generated_output_token(...)` with the
`score-analysis-report` domain. Canonical identity includes exact module/work,
Activity, snapshot revision/hash, report scope, current-head analysis basis, and
selected target identity when applicable.

Display values such as Activity title, target name, Group label, Criterion
label, Scale label, and Standard label never become canonical path components.
Wall-clock generation time is not canonical identity.

## Human-readable standalone filename boundary

Issue #123 does not add a standalone readable-export writer. If a future
explicit teacher workflow adds one, it must use:

```text
concord.generated_paths.build_human_readable_output_filename(...)
```

and inherit #124's byte budgets. It must not add another filename sanitizer,
truncate/hash scheme, append a raw student ID, or treat a readable filename as
canonical identity. Issue #114 remains the primary future consumer of
student-facing/readable filename semantics.

## Filesystem containment and compatibility

Preparation derives output from the selected Concord work root plus the fixed
`exports/score_analysis/` report root. Execution validates the bounded token,
package geometry, fixed leaves, ordinary-directory ancestors, and ordinary
non-symlink existing artifacts.

Issue #123 persists no separate report registry or report-path metadata and
therefore creates no historical report-path reader contract. It requires no
workspace migration and renames no existing Concord state.

## Publication and grading boundaries

Viewing or generating Activity Score Analysis does not create/revise Scores,
Reviews, or Moderation; register Core Academic Work; generate or publish an
Academic Result Manifest; create a Core Publication Record; change Share
attention; or change Meridian state.

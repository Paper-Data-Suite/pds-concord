## Boundaries and behavior

1. The existing opened-Activity normal task choices `1` through `7`, `A` (next action), and Core `B/M/Q` with Concord `H` remain intact. Two distinct teacher-only **read-only** choices are added: `R` = Before class / lesson readiness and `D` = All attention categories. Do not seize `N/P` from normal teacher menus; they are page navigation **inside** the detailed attention screen only.
2. Both screens are fed the **current opened Activity's same read context** or its already-derived attention summary. No new workspace initialization, commits, reclassification, profile write or I/O side effect occurs in view or refresh. Opening the parent again rereads the source. A missing/incomplete source prints a neutral unavailable message, without exception paths or student details. EOF exits the read-only subview. `M/Q` preserve native exception/unwind semantics.
3. Before class presents a **source-backed plan stage**: a single operational applied GroupPlan checked against derived current Group/Membership IDs and Core roster (Slice 1); historical applied but stale/ambiguous requires inspection; proposal-only and no plan do not imply group readiness. When operational, alternative draft/approved plans are *optional*, not blocking. Cancellation stays under existing explicit Plan menu with teacher-reviewed actor/CAS; this view makes no changes.
4. Packet statuses are counted separately as generated, pending preparation or requiring recovery, but **generated** does not certify an output file was printed or distributed. The view explicitly declares printing/distribution *not verified*. It does not imply a physical session occurred, that a child completed work, or that students were assessed.
5. Returned-work status is reported as the number of Artifacts with a canonical matching routed ScanReference to a return-expected page; no scan reference means no **verified routed return record** even if `artifact_status` says returned. Optional-return work is separate from required-return absence; `return_not_expected` and inactive artifacts are not missing-return tasks. Valid matching return references are **not** equivalent to independently inspecting the retained physical file/hash, and the view says so. Contradictory route/source authority raises instead of yielding reassuring readiness.
6. All 20 existing Plan→Prepare→Collect→Review→Score→Share attention codes are shown, in normal order, at most ten per page, without accumulating heterogeneous counts or claiming urgency. No user-supplied code, student name, local file path or raw academic evidence is displayed. A category's owning *normal* task menu is identified by task name; the inspector never silently enters a write-capable flow.
7. **Core's `ModuleReadinessReport` is structural** (workspace/class usable for module operations), not a student's or teacher's before-class checklist. This slice neither changes its schema nor promotes generated PDFs to Core readiness. `ModuleAttentionReport` remains a separately aggregated and owner-routed Concord projection; private Core Notes/Tasks are unrelated.

# v0.3.1 Routine Artifact Review

**Status:** Issue #107 implementation contract and teacher workflow

Issue #107 streamlines first Artifact Review without changing the canonical
`ArtifactReview` model. The optimization is an interaction change: one explicit
teacher decision approves one visible, complete routine Review bundle.

## Teacher workflow

For ordinary returned work:

```text
select Artifact needing Review
    ->
Open returned work
    ->
inspect evidence
    ->
Quick Review
    ->
Ready for scoring
    ->
preview complete Review bundle
    ->
REVIEW
    ->
Review next
```

The selected Review context opens the same exact Artifact through
`open_returned_artifact_evidence(...)`; it does not ask the teacher to select a
second Artifact.

For an exception:

```text
select Artifact needing Review
    ->
Open returned work
    ->
inspect evidence
    ->
Needs detailed review
    ->
Detailed Review
```

Detailed Review retains the existing field-by-field legal Review values and
existing successor/correction behavior.

## Explicit judgment boundary

Quick Review eligibility != automatic Review.

Eligibility only determines whether Concord may offer the ordinary routine form.
No Review exists until the teacher sees the complete proposed bundle and types
`REVIEW`.

Confirmed attribution may permit the shortcut but does not create Review
judgments.

The ordinary routine bundle proposes legal existing values, including readable,
complete, correct filing, confirmed Author and Subject judgments, relevant,
Moderation not required, scoring ready, ready outcome, and teacher-restricted
evidence/Review privacy.

`Ready with qualification` preserves the ordinary bundle while using
`ready_with_qualification` for scoring readiness and outcome and requiring a
teacher note.

## Exact projection and attribution gating

`ArtifactRoutineReviewContext` is an ephemeral read-only projection built from
one exact `ActivityReadContext` loaded by `load_activity_read_context(...)`.

The projection resolves the selected Artifact, current Review head, assembly
state, current Authors, current Subjects, applicable Moderation state, Quick
Review eligibility, teacher-readable exception reasons, snapshot revision, and
snapshot SHA-256.

Current #106 Author/Subject semantics are authoritative. Proposed, disputed,
unknown, unresolved, absent, semantically invalid, or conflicting current
attribution is not silently normalized into a confirmed Review judgment.

Quick Review does not create or modify `ArtifactAuthor` or `ArtifactSubject`
records.

## Snapshot-bound write

`record_routine_artifact_review(...)` generates the routine Review ID internally
and binds the mutation to the exact inspected snapshot revision.

A stale write fails closed. Concord does not silently rebase the teacher's
Review onto newer Artifact, attribution, Review, or Moderation state.

The routine write creates the same canonical `ArtifactReview` record used by
Detailed Review. It creates no `ModerationRecord`, Score, Grade, publication,
Author, or Subject state and does not alter returned-evidence assembly.

## Review next

Review-next eligibility != Quick Review eligibility.

`concord_review_first` remains the authority for whether an Artifact needs its
first Review. `inspect_next_artifact_review(...)` reloads current canonical
Activity state and deterministically selects the first Artifact whose existing
Review-attention state reports `first_review_pending`.

Therefore an Artifact may need a first Review while being ineligible for Quick
Review. Review next must present that Artifact and route it to Detailed Review;
it must not skip it.

No persisted Review queue, cursor, draft, or last-reviewed marker exists.

## Evidence opening

`Open returned work` remains the #105 read-only boundary:

```text
OPEN != ASSEMBLE
OPEN != REVIEW
OPEN != SCORE
```

Opening the selected evidence does not mark it seen or reviewed and does not
change scoring readiness. Existing #105 stale, missing, incomplete, ambiguous,
and integrity failures remain fail-closed.

## Review correction

Quick Review is for first Review only. An existing current Review cannot be
overwritten. Corrections continue to use the established predecessor Review ->
successor Review + `CorrectionRecord` audit model.

## Qualification

Installed-wheel qualification is provided by:

```text
scripts/smoke_test_routine_artifact_review_wheel.py
```

The installed acceptance uses released Core 0.6.3, `pip check`, `python -I`,
site-packages provenance checks, synthetic data, at least two sequential routine
Reviews, and proof that Detailed Review remains reachable.

The runtime dependency remains:

```text
pds-core>=0.6.3,<0.7
```

No existing workspace data migration is required solely for Issue #107.
